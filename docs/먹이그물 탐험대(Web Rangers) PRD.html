                  1. 개요

                  1.1 배경

                  초등 과학의 먹이사슬·먹이그물 수업은 대부분 "누가 누구를 먹는가"를 화살표로 잇는 활동에서 끝납니다. 시중의 카드 게임과 학습 앱도 어휘와 순서 암기에 머무는 경우가 많습니다. 그러나 4학년 교과서도 "개구리가 사라졌을 때 생태계의 변화"(48쪽), "직박구리가 사라지면 어떤 일이 생길지"(49쪽), "분해자가 사라지면 어떤 일이 생길지"(47쪽)를 묻습니다. 이 단원의 핵심은 "한 생물이 사라지거나 늘어나면 연결된 다른 생물에게 어떤 일이 일어나는가"를 추론하는 것입니다.

                  교실에서는 생물 카드로 먹이 관계 모형을 만드는 놀이(교과서 48쪽)나 털실로 학생들을 연결하는 활동(Human Food Web)을 합니다. 하지만 종이 카드와 털실로는 시간에 따른 생물 수의 변화와 간접 효과(예: 개구리가 사라지면 메뚜기가 늘고, 그 결과 풀이 줄어듦)를 눈으로 확인하기 어렵습니다.

                  이 앱은 학생을 생태계의 연쇄 반응을 추리하고 지키는 탐험대원(생태계 관리인)으로 설정하고, 다음 흐름으로 시스템 사고를 연습하게 합니다.

                  1. 생물 카드를 모아 먹이그물을 직접 연결합니다.
                  2. 사건 카드(가뭄, 외래종 유입, 특정 생물이 사라짐 등)가 발동됩니다.
                  3. 무슨 일이 일어날지 먼저 예측합니다.
                  4. 몇 년에 걸쳐 생물 수 막대가 변하는 시뮬레이션을 관찰합니다.
                  5. 예측과 결과를 비교하고, 화살표를 따라 "왜 그렇게 되었는지"를 설명합니다.

                  1.2 목표

                  • 교육 목표 (교과서 42~49쪽 기준)
                  • 생태계를 이루는 생물 요소와 비생물 요소(햇빛, 물, 공기, 흙)를 구분합니다.
                  • 생물 요소를 역할에 따라 생산자·소비자·분해자로 분류합니다.
                  • 먹고 먹히는 관계를 화살표(먹히는 생물 → 먹는 생물)로 나타내고, 먹이사슬과 먹이그물의 차이를 설명합니다.
                  • 한 생물이 사라지거나 늘어나면 직접 연결되지 않은 생물에게까지 영향이 간다는 것(간접 효과)을 추론합니다.
                  • "먹이그물이 복잡하면 어떤 생물이 사라져도 다른 먹이를 먹고 살아갈 수 있어 생태계가 안정적으로 유지된다"(교과서 49쪽)를 시뮬레이션으로 확인합니다.
                  • 교과서의 숲·강·바다 생태계 생물로 먹이그물을 만들고, 외래종·물 오염·바다 쓰레기 같은 실제 환경 문제와 연결합니다.
                  • 제품 목표
                  • 40분 수업 안에 도입부터 정리까지 끝낼 수 있는 흐름을 제공합니다.
                  • 설치·로그인 없이 주소 하나로 바로 실행되고, 학교 와이파이가 불안정해도 동작합니다(오프라인 지원).
                  • 사전·사후 진단 문항을 내장해 교사가 간단히 학습 효과를 확인할 수 있게 합니다.

                  1.3 차별점

                  기존 먹이사슬 게임·활동 먹이그물 탐험대
                  먹이 관계 짝짓기, 순서 맞히기 먹이그물 전체를 만들고 생물 사라짐·사건 시뮬레이션이 핵심
                  정답이 하나인 퀴즈 예측 → 관찰 → 설명 순환(POE: Predict-Observe-Explain)
                  결과만 보여 줌 화살표를 따라 영향이 퍼지는 과정을 애니메이션과 문장으로 설명
                  외국 생물(사자, 얼룩말) 중심 교과서 43~45쪽 숲·강·바다 생태계와 49쪽 먹이그물, 실제 환경 이슈(큰입배스, 바다 쓰레기 등)

                  1.4 범위에서 제외하는 것 (Non-goals)

                  • 로그인, 회원가입, 학생 개인정보(이름 등) 수집, 서버 백엔드
                  • 기기 간 실시간 대전(서버 필요). 모둠 경쟁은 서버 없이 가능한 방식으로만 제공합니다(4장 F8 참고).
                  • 앱 안에서 생성형 AI 호출(아동 대상 서비스의 안전·비용 문제로 제외). 설명 문장은 미리 작성한 템플릿으로 만듭니다. AI는 개발 단계의 그림 제작에만 씁니다(5.5).
                  • 실제 생태학 연구 수준의 정밀한 개체 수 예측. 이 앱의 시뮬레이션은 경향을 보여 주는 단순 모델입니다.
                  • 중학교 범위의 용어(1차·2차 소비자, 영양 단계, 생태 피라미드 등)는 화면에 쓰지 않습니다.
                  • 결제, 광고, 외부 분석 도구(추적 스크립트)

                  2. 사용자와 사용 시나리오

                  2.1 사용자

                  사용자 특징 필요한 것
                  학생(초4) 긴 글 읽기를 어려워하는 학생이 많음. 백분율(%)은 아직 배우지 않음. 크롬북 터치패드 조작이 서툰 학생도 있음. 경쟁과 수집을 좋아함 짧고 쉬운 문장, 큰 버튼, 그림 중심, 즉각적인 피드백, 모으는 재미
                  교사(주 사용자이자 운영자) 40분 안에 수업을 끝내야 함. 기기 문제에 대응할 시간이 부족함 바로 켜지는 앱, 전자칠판용 진행 화면, 교과서 차시와 맞는 활동, 결과 확인
                  개발자(본인) 바이브 코딩으로 개발. 콘텐츠(생물 데이터)와 그림(AI 생성)도 직접 준비 단순한 구조, 데이터와 로직 분리, 검증 테스트, 그림 프롬프트

                  2.2 사용 환경

                  기기 사양 설계 기준
                  학생 크롬북 1280×800, 크롬 브라우저, 터치패드(일부 기종은 터치스크린) 브라우저 탭·주소창을 뺀 실제 화면 약 1280×690에서 스크롤 없이 핵심 조작 가능. 전체 화면(키보드의 전체 화면 키)에서는 1280×800
                  교사 전자칠판 1920×1080(Full-HD), 엣지 브라우저, 터치 윈도우 화면 배율이 150%이면 실제 CSS 화면은 1280×720, 100%이면 1920×1080. 두 경우 모두 깨지지 않게 화면 크기에 비례해 커지는 레이아웃
                  • 학생 1인 1기기(크롬북). 모둠 활동은 전자칠판 1대로 진행합니다.
                  • 학교 기기는 여러 반이 함께 쓰므로, 기기에 남는 데이터는 학생 번호(예: 4학년 2반 13번)만 사용합니다.

                  2.3 대표 수업 시나리오

                  4학년 2반, 과학 2단원 '생물과 환경' 중 "생물의 먹고 먹히는 관계를 알아볼까?"(교과서 48~49쪽) 차시와 그다음 차시. 학생 24명, 크롬북 24대, 전자칠판 1대.

                  1차시(40분): 먹이그물 만들기 — 교과서 48~49쪽 1. (5분) 교사가 전자칠판에서 앱을 열고 수업 모드를 켭니다. 학생은 크롬북에서 같은 주소를 열고 학년·반·번호를 입력합니다. 2. (5분) 학생이 사전 진단 6문항을 풉니다. 3. (5분) 튜토리얼: 카드 3장으로 먹이사슬(풀 → 메뚜기 → 개구리)을 잇고, 화살표 방향의 뜻을 배웁니다(교과서 49쪽 먹이사슬 예시). 4. (15분) 먹이그물 만들기: 교과서 49쪽 숲 생물 카드 14장을 화살표로 잇습니다. 교과서 "도우미"처럼 생산자 카드부터 시작하도록 안내합니다. 틀린 연결은 바로 알려 주고 힌트를 줍니다. 5. (10분) 교사가 전자칠판에서 완성된 먹이그물을 띄우고 교과서 질문을 함께 이야기합니다. "먹이사슬과 무엇이 다른가요?" "개구리가 사라지면 어떻게 될까요?"

                  2차시(40분): 사건 탐구(생태계 관리인) 1. (18분) 사건 탐구: 사건 카드 "개구리가 모두 사라졌어요"(교과서 48쪽 질문)가 나옵니다. 학생은 풀이 어떻게 될지 예측하고, 가장 크게 변할 생물을 고릅니다. 8년 동안의 변화를 관찰하고 점수를 받습니다. 이어서 "직박구리가 사라졌어요"(교과서 49쪽 질문)를 탐구합니다. 2.                   6. 시뮬레이션 모델

                  6.1 설계 원칙

                  • 학생이 결과를 보고 "화살표를 따라가면 이해가 되는" 수준의 단순 모델을 씁니다.
                  • 기본 형태는 생태학의 로트카-볼테라(Lotka-Volterra) 포식자-피식자 모델을 단순화한 턴제 계산입니다.
                  • 화면에는 수식을 보여 주지 않습니다. 교사 가이드에만 원리를 쉬운 말로 설명합니다.

                  6.2 계산식

                  생물 수를 처음 값 1.0(화면 표시는 100)으로 맞춰 계산합니다. 1년(한 턴)은 작은 계산 단계 10번(dt = 0.1)으로 나누어 계산해 값이 튀지 않게 합니다.

                  생산자 i

                  변화량 = r_i × N_i × (1 − N_i / (K_i × E_i × S_i)) − Σ_j a_ij × N_i × N_j
                  • r_i: 성장률, K_i: 최대 한도, E_i: 비생물 요소 계수(가뭄·장마 때 1보다 작음), S_i: 양분 계수(분해자 상태에 따라 0.7~1.0)
                  • Σ_j: 생산자 i를 먹는 모든 소비자 j

                  소비자 j

                  변화량 = e × Σ_i a_ij × N_i × N_j  −  Σ_k a_jk × N_j × N_k  −  m_j × N_j
                  • 첫째 항: 먹이에서 얻는 성장(e: 먹이 전환 효율)
                  • 둘째 항: 나를 먹는 동물 k에게 먹혀서 줄어듦
                  • 셋째 항: 자연 사망(m_j: 사망률)

                  분해자 d와 쌓인 찌꺼기 D

                  찌꺼기 변화량 = (그해 죽은 양의 합) − b × N_d × D
분해자 변화량 = e_d × b × N_d × D − m_d × N_d
양분 계수 S = 0.7 + 0.3 × min(1, N_d)
                  • 분해자가 줄면 찌꺼기가 쌓이고 양분 계수가 떨어져 생산자가 천천히 줄어듭니다.

                  공통 처리 - 모든 값은 0 이상, 상한 3.0(화면 300)으로 제한합니다. - 0.02(화면 2) 미만이 되면 0으로 만들고 "사라짐" 상태로 바꿉니다.

                  6.3 자동 보정(균형 상태 만들기)

                  생물 데이터를 작성할 때 계수를 일일이 맞추기는 어렵습니다. 그래서 모든 생물이 1.0일 때 변화량이 0이 되도록 계수를 자동으로 계산합니다.

                  1. 데이터에는 먹이 관계와 먹이 선호도(예: 뱀은 개구리 40%, 다람쥐 30%, 직박구리 20%, 토끼 10%)만 적습니다.
                  2. 선호도에 소비자별 섭식량 c_j를 곱해 a_ij를 정합니다.
                  3. 소비자 사망률: m_j = e × Σ_i a_ij − Σ_k a_jk (균형 조건에서 역산). 값이 0 이하이면 데이터 오류로 보고 빌드 단계에서 경고합니다.
                  4. 생산자 최대 한도: K_i = 1 / (1 − Σ_j a_ij / r_i) (Σ_j a_ij < r_i 이어야 함).

                  이렇게 하면 사건이 없을 때 생태계가 저절로 균형을 유지하고, 사건이 생긴 뒤의 변화만 관찰할 수 있습니다.

                  6.4 안정성 확보

                  로트카-볼테라 모델은 진동(늘었다 줄었다 반복)이 커질 수 있습니다. 다음 장치로 4학년이 이해하기 쉬운 변화 곡선을 만듭니다. - 포식자 간섭 항(같은 포식자끼리 경쟁)으로 진동 줄이기 - 계산 단계를 잘게 나누기(dt = 0.1) - 자동 테스트(6.6)로 테마별 안정성과 사건별 결과 방향을 검증

                  6.5 설명 문장 생성

                  매년 생물별로 변화량의 각 항(먹이에서 얻는 양, 먹히는 양, 사건 효과)을 처음 상태와 비교해 가장 큰 까닭을 찾고, 템플릿 문장으로 바꿉니다.

                  까닭 템플릿
                  먹이 감소 "{생물}이(가) 줄었어요. 먹이인 {먹이}이(가) 줄었기 때문이에요."
                  먹이 증가 "{생물}이(가) 늘었어요. 먹이인 {먹이}이(가) 많아졌기 때문이에요."
                  먹는 동물 증가 "{생물}이(가) 줄었어요. {생물}을(를) 먹는 {동물}이(가) 늘었기 때문이에요."
                  먹는 동물 감소 "{생물}이(가) 늘었어요. {생물}을(를) 먹는 {동물}이(가) 줄었기 때문이에요."
                  먹이 여러 가지 "{생물}은(는) {먹이1}이(가) 사라졌지만 {먹이2}을(를) 먹어서 크게 줄지 않았어요."
                  사건 직접 영향 "{사건} 때문에 {생물}이(가) 바로 줄었어요."
                  • 한국어 조사(이/가, 을/를, 은/는)는 받침 여부로 자동 선택합니다.
                  • 이 기록을 거꾸로 따라가면 "개구리 사라짐 → 메뚜기 늘어남 → 풀 줄어듦" 같은 영향이 퍼진 길을 만들 수 있고, 질문 3의 정답과 화살표 빛 애니메이션에 사용합니다.

                  6.6 시뮬레이션 검증 테스트

                  테스트 기준
                  무사건 안정성 30년 동안 모든 생물이 100 ±2 안에 머묾
                  복원력 한 생물을 20 줄인 뒤 30년 안에 100 ±5 안으로 돌아옴
                  교과서 정답 일치 숲: "개구리 사라짐 → 메뚜기 늘어남 → 풀 줄어듦", "분해자 사라짐 → 생산자 서서히 줄어듦", "먹이사슬보다 먹이그물에서 변화가 작음"이 성립
                  출제 품질 스테이지 질문의 정답 생물 결과가 88~112 밖에 있음(애매하지 않음)
                  데이터 검증 모든 소비자에게 먹이가 1개 이상, 사망률 > 0, 생산자 조건 충족, 교과서 대조표와 숲 관계 목록 일치
                  어휘 검사 화면 문장에 금지어(1차 소비자, 개체 수, 천적, 영양 단계 등)가 없음

                  변화는 바로 일어난다 해마다 재생해 시간 차이 관찰("3년 뒤에야 풀이 줄기 시작했어요")
                  분해자는 중요하지 않다 숲 스테이지 3 "버섯과 곰팡이가 사라졌어요" → 찌꺼기가 쌓이고 생산자가 서서히 줄어듦
                  비생물 요소는 생물과 관계없다 숲 스테이지 4 "가뭄" → 생산자부터 줄고 소비자에게 이어짐
                  시뮬레이션 결과 = 실제 자연 결과 화면에 "실제 자연은 날씨, 병 등 더 많은 것이 영향을 줘요" 안내, 교사 가이드에 모델 한계 설명

                  8. 기술 스택

                  영역 선택 이유
                  프레임워크 React + TypeScript + Vite 바이브 코딩 자료가 많고, 타입으로 데이터 오류를 줄임
                  먹이그물 시각화 D3.js(d3-force) + SVG 힘 기반 배치에 층별 세로 위치 힘(forceY)을 더해 "아래 생산자 → 위 먹는 동물" 구조 유지. 숲은 교과서 그림과 비슷한 고정 좌표를 초기값으로 사용
                  화살표 잇기 SVG 포인터 이벤트(Pointer Events) 직접 구현 마우스·터치패드·터치를 한 코드로 처리. "끌어서 잇기"와 "눌러서 잇기" 모두 지원
                  생물 수 막대·그래프 CSS 막대 + 간단한 SVG 꺾은선 라이브러리 없이 충분, 애니메이션 제어 쉬움
                  상태 관리 Zustand 단순하고 코드가 짧음
                  시뮬레이션 엔진 순수 TypeScript 모듈(화면과 분리) 단위 테스트(Vitest)로 검증, 모둠 대항전 결정론 보장
                  저장 localStorage 학생 번호별 진행 상황, 수 KB 수준
                  오프라인 PWA(vite-plugin-pwa) 학교 와이파이 불안정 대응. 크롬·엣지 모두 PWA 설치 지원
                  그림 AI 생성 PNG → WebP 변환(256·512px 두 크기) 크롬북에서 빠르게 불러오기, 오프라인 캐시 용량 절약
                  음성(P1) Web Speech API(speechSynthesis, 한국어) 진단 문항 읽어 주기. 크롬북 기본 음성 사용
                  효과음 Web Audio(짧은 효과음 몇 개) 교실 기본값은 소리 끔

                  탐구 보고서 점수, 질문별 결과, 영향이 퍼진 길, 생물별 설명, 관리인 행동
                  자유 실험실 먹이그물 + 생물 누름 메뉴(없애기/줄이기/늘리기), 사건 선택, 꺾은선 그래프, 먹이사슬 비교
                  도감 테마별 탭, 카드 격자, 카드 상세(먹이·나를 먹는 동물)
                  진단 한 화면에 한 문항, 큰 보기 버튼, 읽어 주기 버튼, 진행 표시
                  교사 수업 모드, 모둠 대항전, 기기별 결과, CSV 내보내기, 카드 열기, 데이터 지우기

                  11. 비기능 요구사항

                  항목 기준
                  대상 기기 학생 크롬북(1280×800, 크롬 최신판), 전자칠판(1920×1080, 엣지 최신판, 윈도우 화면 배율 100~150%)
                  화면 크기 1280×690(크롬북 브라우저 창), 1280×720(전자칠판 150% 배율), 1920×1080(전자칠판 100% 배율)에서 깨지지 않음. 크롬북에서 핵심 조작은 스크롤 없이 보임
                  입력 마우스·터치패드·터치 모두 지원(Pointer Events). 끌기가 어려운 경우를 위한 "눌러서 잇기·눌러서 넣기" 제공. 마우스를 올렸을 때의 효과(hover)에만 의존하는 기능 없음
                  성능 첫 화면 3초 이내(학교 와이파이 기준), 시뮬레이션 재생 중 끊김 없음(초당 30프레임 이상, 보급형 크롬북 기준)
                  오프라인 한 번 접속한 뒤에는 인터넷 없이 모든 기능 사용 가능(그림·글꼴 포함)
                  누르는 영역 크롬북 버튼·카드 최소 44×44px, 전자칠판 버튼 최소 64×64px. 가까운 카드에 화살표가 자동으로 붙는 자석 효과
                  글 4학년 어휘, 한 문장 25자 안팎, % 대신 수, 어려운 낱말(생산자 등)은 누르면 뜻 풀이
                  접근성 색 + 기호 + 글자로 변화 표시(▲ 늘어요/▼ 줄어요), 고대비 모드, 글자 크기 2단계, 문항 읽어 주기(P1)
                  개인정보 이름·사진 등 개인정보 수집 없음, 외부 전송 없음, 추적 스크립트 없음
                  소리 기본값 끔(교실), 켜면 짧은 효과음만
                  수업 시간 한 판(사건 탐구) 5~7분, 먹이그물 만들기 10~15분, 분류 놀이 5~10분

                  12. 개발 단계 (마일스톤)

                  M1. 데이터와 시뮬레이션 엔진 (화면 없음)

                  • 숲(교과서 49쪽) 데이터 작성, 자동 보정·턴 계산·사건 효과 구현
                  • 6.6 검증 테스트 통과, 명령줄에서 사건별 결과 표 출력
                  • Claude 검토: 교과서 대조표(32개 관계, 교사 확인 완료)와 데이터 일치 확인
                  • 완료 기준: "개구리 사라짐 → 메뚜기 늘어남 → 풀 줄어듦"이 테스트로 확인됨

                  M2. 그림 1차와 먹이그물 만들기

                  • 기준 그림과 숲 생물 16장 생성(5.5), 그림 검수
                  • 층 배치 판, 끌어서 잇기·눌러서 잇기, 즉시 판정·힌트, 자동 정렬, 튜토리얼(먹이사슬 3장)
                  • 분류 놀이(생산자·소비자·분해자)
                  • 완료 기준: 크롬북에서 숲 먹이그물을 15분 안에 완성할 수 있음

                  M3. 사건 탐구(핵심 게임 루프)

                  • 사건 발동 → 예측 → 시뮬레이션 재생 → 채점·설명 → 관리인 행동 → 별
                  • 설명 문장 생성, 영향이 퍼진 길 애니메이션
                  • 숲 5개 스테이지(먹이사슬 비교 포함), 자유 실험실
                  • 완료 기준: 숲 테마로 교과서 48~49쪽 차시 수업 진행 가능

                  M4. 교실 기능과 모둠 대항전(전자칠판 진행형)

                  • 학생 번호 관리, 사전·사후 진단, 교사 결과 화면·CSV
                  • 모둠 대항전 전자칠판 진행형(F8-1~F8-4), 1920×1080·엣지 화면 최적화
                  • PWA 오프라인, 교사 가이드
                  • 완료 기준: 실제 교실 기기(크롬북 + 전자칠판)에서 2차시 수업 리허설 성공

                  M5. 강·바다 콘텐츠와 카드 수집

                  • 강·바다 데이터·사건·스테이지(각 3개), 그림 2차(강·바다·사건·행동 카드)
                  • 카드 도감과 보상, 생물·비생물 요소 분류 놀이(F11-2)
                  • Claude 검토 → 과학 담당 교사 검토
                  • 완료 기준: 세 테마 모두 검증 테스트 통과, 콘텐츠 검토 의견 반영

                  M6. 파일럿 수업과 도전 코드형

                  • 1~2개 학급에서 파일럿, 사전·사후 진단 비교, 난이도·문장 수정
                  • 모둠 대항전 도전 코드형(F8-5), 실험 기록장 등 P1·P2 기능 추가

                  13. 위험 요소와 대응

                  위험 영향 대응
                  시뮬레이션 결과가 교과서 설명과 다름 학생 혼란, 교사 신뢰 하락 교과서 정답 일치 테스트, 애매한 문제 자동 제외, 결과마다 설명 문장 제공
                  교과서 그림 판독 오류 잘못된 먹이 관계 학습 5.4 대조표를 교사가 확인 완료. 데이터와 대조표 일치를 자동 테스트로 유지
                  강·바다에 교과서 밖 생물을 추가함 교과서와 달라 혼란 꼭 필요한 생물만 추가하고 "추가" 표시(교사 확인 완료). 수업에서 "교과서에는 없지만 이 생태계에 사는 생물"로 소개
                  진동이 커서 결과가 이상하게 출렁임 해석 어려움 포식자 간섭 항, 작은 계산 단계, 안정성 테스트
                  숲 먹이그물(16종, 화살표 32개)이 4학년에게 복잡함 완성 못 함, 흥미 저하 생산자부터 단계적 안내, 눌러서 잇기, 힌트, 80% 완성 기준, 분해자 연결 숨김
                  크롬북 터치패드로 끌기가 어려움 조작 실패 눌러서 잇기·눌러서 넣기, 큰 카드, 자석 효과
                  전자칠판 배율·해상도 차이 화면 깨짐 1280×720~1920×1080 비례 레이아웃, 세 화면 크기 자동 테스트
                  AI 그림의 생물 특징 오류·화풍 불일치 잘못된 개념, 완성도 저하 기준 그림 + 상세 프롬프트, 그림 검수 점검표, 필요 시 다시 생성
                  공용 기기에 학생 기록이 섞임 결과 신뢰도 저하 학생 바꾸기 버튼, 수업 시작 시 번호 확인, 교사의 데이터 지우기 기능
                  경쟁이 과열되어 추론보다 찍기에 집중 학습 효과 저하 질문 3(까닭)에 배점, 모둠 토의 시간 확보, 오답에도 설명 제공
                  효과 검증 연구 부족(근거 강도 ★☆☆) 효과 불확실 사전·사후 진단 내장, 파일럿에서 간단한 효과 측정

                  14. 성공 지표

                  • 데이터: 로그인 없이 기기에 저장, 학생은 학년·반·번호만 입력, 결과는 교사 화면과 CSV로 확인
                  • MVP 테마: 교과서와 같은 숲·강·바다(숲 5개, 강·바다 각 3개 스테이지)
                  • 먹이 관계: 숲 32개(교과서 49쪽), 강 12개, 바다 13개 모두 교사 확인 완료
                  • 개발 기준 자료: 교과서(실험관찰은 참고하지 않음)
                  • 그림: AI 이미지 생성(프롬프트 문서 제공), 앱 안에서는 생성형 AI를 쓰지 않음
                  • 콘텐츠 검토: Claude 1차 검토 → 개발자 → 과학 담당 교사
