## 1. 콘셉트: 탐험 수첩 × 생물 도감

학생은 생태계에 일어난 사건의 까닭을 화살표를 따라 추리하는 **탐험대원**입니다. 화면은 **크라프트지 수첩** 위에 생물 카드와 메모를 붙여 둔 느낌으로 만듭니다.

- **바탕**: 따뜻한 종이색과 옅은 점 격자(수첩 모눈)
- **브랜드 색**: 탐험대 조끼의 **남색**과 돋보기의 **금색**
- **사건 카드**: 검은 테두리와 각진 그림자로 소식지처럼 표현해, 평소 화면과 확실히 구분합니다.
- **생물 색**: 교과서 분류(생산자·소비자·분해자)마다 고정된 색을 씁니다.
- **그림**: 교과서 49쪽처럼 실제 모습에 충실한 수채 색연필 세밀화(AI 생성).

### 디자인 원칙
1. **교과서와 같게**: 숲 먹이그물은 교과서 49쪽 생물·관계를 그대로 쓰고, 용어도 교과서와 같게 씁니다(먹이사슬·먹이그물 붙여 쓰기, 생산자·소비자·분해자). 1차·2차 소비자, 개체 수, 천적 같은 말은 쓰지 않습니다.
2. **화살표가 주인공**: 먹이그물의 화살표와 영향의 흐름이 가장 눈에 띄어야 합니다.
3. **색만으로 말하지 않기**: 늘어남·줄어듦은 **색 + 기호(▲▼●) + 수**로, 역할은 **색 + 아이콘 + 글자**로 함께 표시합니다.
4. **4학년에게 맞게**: 문장은 25자 안팎, % 대신 "100 → 136"처럼 수로, 시간은 "1년, 2년"으로 보여 줍니다. 보기는 3~4개로 줄입니다.
5. **두 기기, 한 디자인**: 크롬북에서는 스크롤 없이 핵심 조작이 보이고, 전자칠판에서는 같은 구성이 비례해 커집니다.

## 3. 화면 기준

| 기기 | 해상도·브라우저 | 실제 그릴 수 있는 영역 | 설계 규칙 |
|---|---|---|---|
| 학생 크롬북 | 1280×800, 크롬 | 탭·주소창을 빼면 약 **1280×690** (전체 화면이면 1280×800) | 01~05·07 화면은 1280×690 안에 스크롤 없이 들어가야 함. 06 보고서는 세로 스크롤 허용 |

## 6. 레이아웃

- **앱 바**(높이 약 64px): 로고, 위치(숲 › 사건 탐구 1), 진행 단계(사건 → 예측 → 관찰 → 보고서), 별·카드·학생 번호.
- **2단 배치**: 왼쪽 "보는 것"(사건 카드, 먹이그물), 오른쪽 "하는 것"(예측, 막대, 행동). 화면 폭이 1000px 미만이면 위아래로 쌓습니다.
- **먹이그물 판**: SVG `viewBox 0 0 960 530`. 먹히는 생물은 아래, 먹는 생물은 위로 5층(y = 470 / 365 / 260 / 160 / 60)에 놓고, 분해자는 오른쪽 아래 점선 상자에 둡니다. 숲은 선이 생물 그림을 지나가지 않도록 맞춘 고정 좌표를 씁니다(시안 스크립트 `N`).
- **크롬북 높이 예산(1280×690)**: 앱 바 64 + 위아래 여백 24 + 도구줄 48 + 간격 12 + 본문 약 540px.

## 7. 컴포넌트 명세

### 7.1 FoodWebCanvas (먹이그물)
| 요소 | 명세 |
|---|---|
| 노드 | 반지름 32px 원, 테두리 5px 역할색, 가운데 그림, 아래 이름(흰 테두리 글자) |
| 화살표 | 2.4px 선 + 끝 삼각형. 방향은 **먹히는 생물 → 먹는 생물** |
| 상태: 연결 성공 | 초록 실선 |
| 상태: 잘못된 연결 | 빨강 점선 + 피드백 띠 |
| 상태: 힌트 | 금색 짧은 점선 |
| 상태: 영향 흐름 | 금색 4.5px 점선이 화살표 방향으로 흐르는 애니메이션(1초 주기) |
| 상태: 흐림 | 흐름이 없는 나머지 화살표는 `#DDD4C2` |
| 노드: 사건 대상 | 금색 링이 커졌다 작아지는 맥박 효과 |
| 노드: 눌러서 잇기 선택됨 | 남색 점선 링(다음에 누를 "먹는 생물"을 기다리는 상태) |
| 노드: 아직 놓지 않음 | 투명도 30% |
| 노드: 사라짐 | 회색 바탕 + 점선 테두리 + 흐린 그림 |
| 변화 배지 | 노드 오른쪽 위 `▲136`, `▼84`(110 초과·90 미만일 때만) |
| 분해자 연결 | 갈색 가는 점선, 기본 숨김(스위치로 표시) |

### 7.2 화살표 잇기 입력
| 방법 | 동작 | 대상 |
|---|---|---|
| 끌어서 잇기 | 먹히는 생물에서 누른 채 끌어 먹는 생물에 놓기. 가까운 노드에 자석처럼 붙음 | 터치스크린, 마우스 |
| 눌러서 잇기 | 먹히는 생물을 누름(남색 점선 링) → 먹는 생물을 누름 → 화살표 생성. 빈 곳을 누르면 취소 | **크롬북 터치패드**, 끌기가 어려운 학생 |

- 두 방법 모두 Pointer Events 하나로 처리합니다. 마우스를 올렸을 때만 보이는 정보는 두지 않습니다.

### 7.3 SpeciesCard (생물 카드)
- **작은 카드**(보관함): 42px 그림 상자 + 이름 + 역할 배지. 그림 상자 아래 4px 역할색 띠.
- **분류 카드**: 104px 너비, 큰 그림 + 이름(역할 배지 없음, 학생이 직접 분류하므로).
- **도감 카드**: 위 72px 그림, 아래 5px 역할색 띠, 이름과 배지.
- **잠김**: 그림을 검은 실루엣으로, 이름은 `???`.
- **특별(멸종위기·외래종)**: 금색 테두리. 상세에 빨간 "멸종위기 야생생물" 또는 "생태계를 어지럽히는 생물" 태그.
- **끄는 중·선택됨**: −3° 기울기, 남색 테두리, 큰 그림자.

### 7.4 SortBins (분류 놀이 바구니)
- 3칸 바구니: 역할색 점선 테두리 + 옅은 바탕 + 아이콘·이름 + 교과서 정의 한 줄(교과서 47쪽 문장을 쉽게).
- 넣을 수 있는 바구니는 남색 외곽선으로 강조. 맞으면 초록 띠에 까닭 설명, 틀리면 빨간 띠에 힌트.
- 상단 전환: "생산자·소비자·분해자" / "생물 요소·비생물 요소".

### 7.5 EventCard (사건 카드)
- 검은 3px 테두리 + `5px 5px 0` 각진 그림자, −1° 기울기.
- 머리띠: `📰 숲속 소식` / 교과서 연결(예: "교과서 48쪽 질문").
- 그림 + 도장(`사라짐`, 빨간 테두리, 12° 기울기) + 제목 + 2문장 설명 + 변화 칩(`✕ 개구리 100 → 0`).

### 7.6 PredictionPanel (예측)
- 질문마다 남색 번호 원 + 굵은 질문 + 오른쪽 배점 칩.
- **질문 1**: 3칸 큰 버튼(높이 54px) ▲늘어요 / ▼줄어요 / ●비슷해요.
- **질문 2**: 그림 카드 **4개**(사건이 직접 건드린 생물 제외).
- **질문 3**: 그림 기호(`🐸✕ → 🦗▲ → 🌿▼`)가 붙은 짧은 문장 보기 3개.
- "🔊 읽어 주기" 버튼(P1). 세 질문을 모두 답해야 "예측 제출" 버튼이 활성화됩니다.

### 7.7 PopulationBars · YearTimeline (관찰)
- 막대 한 줄(높이 약 26px): 그림 / 이름 / 막대 / 변화 칩. 막대 최대값 150, 처음 값 100 위치에 세로 점선. 12줄까지 크롬북 화면에 들어갑니다.
- 막대 채움은 역할색, 변화 칩은 변화색으로 역할과 변화를 구분합니다. 예측에 나온 생물 줄은 금색 바탕으로 강조.
- 타임라인: `처음, 1년 … 8년` 알약 모양. 지난 해(옅은 남색) / 현재(남색 + 금색 테두리) / 남은 해(종이색).
- 버튼: ▶ 재생(⏸ 멈춤, 1.1초에 1년) / 1년 ⏭ / ↺ 처음부터. 막대 아래 해설 말풍선(PRD 6.5 템플릿).

### 7.8 ScoreCard · InfluenceChain (탐구 보고서)
- 점수 카드: 맞음(초록 테두리 + ○) / 틀림(빨강 테두리 + ✕), 내 답과 실제 결과(`▼ 100 → 84`), 점수.
- 영향이 퍼진 길: 생물 카드 → 금색 화살표 → 생물 카드.
- 설명 카드 + 교과서 문장 한 줄("먹이그물이 복잡하면 … 교과서 49쪽").

### 7.9 ActionCard (관리인 행동)
- 큰 그림 + 이름 + 효과 한 줄. 1장만 선택(예산 없음). 선택 시 초록 테두리.
- 지금 쓸 수 없는 행동은 흐리게 하고 까닭을 적습니다("지금은 가뭄이 아니라 필요 없어요").

### 7.10 TeamBoard (모둠 대항전, 전자칠판)
- 어두운 남색(`#1E2B3D`) 바탕, 16:9, 모든 크기를 `cqw`(화면 너비 기준)로 지정.
- 큰 사건 카드 + 원형 타이머(금색 진행 링).
- 모둠 타일 6개(가로 한 줄): 이름 + ▲▼● 큰 버튼(최소 64px, 남는 높이를 채움) + 상태. 입력을 마친 모둠은 금색 테두리.
- **답 가리기**(기본 켬): 공개 전까지 고른 답을 표시하지 않고 "✔ 입력 완료"만 보여 줍니다.
- 점수판: 순위(금색 숫자) + 금색 막대 + 점수. 오른쪽 아래에 "모두 공개하고 관찰하기" 큰 버튼.

## 8. 화면별 명세

### 01 메인
- 인사 영역(탐험대 배지 72px) + 테마 카드 3장(그림 영역, 사건 진행 태그, 별, 진행 막대, 숲·강·바다에 각각 `교과서 49쪽`·`44쪽`·`45쪽` 꼬리표) + 모드 4개(분류 놀이 / 먹이그물 만들기 / 사건 탐구 / 자유 실험실).

### 02 분류 놀이
- 위: 안내 문장 + 남은 카드 수. 가운데: 분류할 카드 줄(교과서 47쪽 예시 생물과 테마 생물). 아래: 바구니 3개. 맨 아래: 피드백 띠.

### 03 먹이그물 만들기
- 위: 이은 화살표 진행률(예: 19 / 32), 힌트, 정리하기, 분해자 연결 보기.
- 왼쪽: 카드 보관함 + 피드백 + 잇는 방법. 처음에는 생산자 카드가 맨 위(교과서 48쪽 "생산자 카드부터 시작").
- 가운데: 먹이그물 판(최대 높이 500px).

### 04 사건·예측
- 왼쪽: 사건 카드 + 대상이 깜빡이는 먹이그물(작게). 오른쪽: 예측 질문 3개 + 읽어 주기 + 제출.

### 05 관찰
- 위: 사건 띠 + 타임라인 + 재생 버튼. 왼쪽: 영향이 흐르는 먹이그물(사라진 생물은 점선 원). 오른쪽: 생물 수 막대 12줄 + 해설.

### 06 탐구 보고서
- 총점·별·보상 → 질문별 결과 → 영향이 퍼진 길·설명 → 관리인 행동 → "행동하고 4년 더 지켜보기". 세로 스크롤 허용.

### 07 카드 도감
- 위: 테마 탭(수집 수). 왼쪽: 카드 격자. 오른쪽: 상세(그림, 보호 태그, 사는 곳·먹이·나를 먹는 동물, 한 줄 사실).

### 08 모둠 대항전
- 전자칠판 전체 화면. 사건 카드·타이머 → 모둠 입력 → 공개 → 함께 관찰 → 점수판.

### 09 교사 화면
- 요약 수치 4개, 학생별 표(사전→사후, 간접 효과 문항, 까닭 쓰기, 진행, 예측 정답률), 자동 안내, CSV·카드 열기.

## 9. 그림 방향 (AI 생성)

- **화풍**: 교과서 49쪽 그림과 어울리는 **수채 + 색연필 세밀화**. 귀엽게 바꾸지 않고, 종의 특징(무늬, 부리, 다리 수)을 정확하게.
- **생물 카드**: 흰 배경, 생물 하나, 3/4 측면, 몸 전체. 배경을 지워 투명 PNG → WebP(512·256px).
- **사건·행동 카드**: 4:3 장면 그림. 사라짐은 빈 서식지와 흐린 실루엣으로 표현하고, 다치거나 죽은 동물은 그리지 않음.
- **분해자·플랑크톤**: 눈에 잘 보이지 않는 생물은 "확대 원(돋보기)" 안에 그려 탐험 콘셉트와 연결.
- 역할색은 그림에 넣지 않고 테두리·띠로만 표현해, 그림을 바꿔도 체계가 유지되게 합니다.
- 프롬프트, 작업 순서, 검수 점검표는 `image-prompts.md`를 따릅니다. 시안의 이모지는 자리 표시용입니다.

## 12. 구현 지침 (바이브 코딩용)

1. 4장의 토큰을 `src/styles/tokens.css`에 CSS 변수로 옮기고, 컴포넌트에서는 변수만 씁니다.
2. 먹이그물은 시안의 `draw()` 함수처럼 **데이터(노드·관계) → SVG** 구조로 만듭니다. 숲은 시안 좌표(`N`)를 그대로 쓰고, 강·바다는 d3-force + `forceY(층)`로 배치한 뒤 좌표를 저장해 고정합니다.
3. 화살표 끝은 노드 반지름(32px) + 여유 4px만큼 줄여 그려야 화살촉이 원에 가려지지 않습니다.
4. 막대와 변화 칩의 판정(110/90)은 엔진의 채점 함수와 **같은 함수**를 씁니다.
5. 전자칠판 화면(`TeamBoard`)은 `container-type: inline-size`를 주고 모든 크기를 `cqw`로 지정합니다. 엣지 배율 100%·150% 모두 같은 모습이 됩니다.
6. 크롬북 화면은 Playwright로 1280×690에서 `scrollHeight ≤ clientHeight`인지(06·10 화면 제외) 자동 확인합니다.
7. 시안에 없는 화면(시작·번호 입력, 진단, 자유 실험실, 설정)은 01·02·04 화면의 패널·버튼·보기 컴포넌트를 조합해 만듭니다.
